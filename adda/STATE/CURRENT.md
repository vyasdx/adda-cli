# Current State

updated: 2026-11-14
summary: v0.5.8 treats the repository it reads as untrusted input (ADR-0030): the commit hook and `doctor` start Python without the repository root on the import path (a committed `json.py` ran under `-m`), no output is written through a symlink the repository planted, git calls ignore programs named in the repository's own git config, map paths stay inside the repository, and the release pipeline is split, environment-gated and SHA-pinned; re-run `adda hook install --force` to replace a hook installed earlier. v0.5.7 makes `audit --refs` precise on instruction files written by other teams: a cited name counts only when its sentence claims it exists (ADR-0028), names and paths are read the way repositories write them (ADR-0029), a leading `/` means the repository root, foo/bar names are placeholders, an empty git index no longer hides committed files, and the name corpus is read in parallel (deno 149 s to 8 s); measured on 83 public repositories in `benchmarks/case-study-2026-11.md`. v0.5.6 says what leaves the machine: `monitor --file`'s help names when a file's text goes to Anthropic's token counter, and the README gains a "What leaves your machine" section (ADR-0027); `audit --refs` also reads `REVIEW.md` (ADR-0026). v0.5.5 makes `hook install` refuse (unless `--force`) a hooks folder outside the repository, which an absolute `core.hooksPath` copied with `.git/config` points at, and `doctor` fails the same case. v0.5.4 imports a product's existing code-to-doc map in any of the shapes products keep them (`modules` with `owns` / `covers` / `file`, `repos` with a `root`, `mappings`), wildcards and folders covering the text files git sees (ADR-0025), and `--refs` reads `.github` workflows for names. v0.5.3 makes a working tree read like a clean checkout: `sync`, `audit` and `--refs` skip git-ignored files and nested repositories (ADR-0024), and `audit --refs` splits its total between audit and --refs findings. v0.5.2 makes ADDA safe to roll out on real products: `audit --refs` looks up names in every non-prose file - SQL, Prisma, shell, config - and leaves `.git/` paths alone (ADR-0022); `sync --map` keeps a product's own entries for any file, migrations and schemas included; `sync --map --from` imports a map a product already keeps (ADR-0023); `monitor` knows the 1M-context 5.x models. v0.5.1 adds the two rollout accelerators: `audit --refs` checks markdown links in instruction files (ADR-0020), and `sync --map` points new code at the module doc that already names it (ADR-0021). v0.5.0 extends the checks beyond module docs and proves the gate is on. `audit --refs` checks the names and paths cited in docs and in every coding agent's instruction files (ADR-0011, 0012, 0014); `doctor` proves the commit gate is installed where git reads hooks and can run (ADR-0015); `memory` audits an agent's memory folder (ADR-0016); `restated` lists copies of text a correction removed (ADR-0017). `sync --map` keeps a product's own doc choices across regenerates (ADR-0013, 0019), which the fleet rollout depends on. v0.4.0 made every check say what it could not determine; that still holds.

## Notes
- Fifteen commands. The test count is not recorded here - CI derives it (`scripts/check_counts.py`); a hand-kept number drifted five times. OKF schema locked at v0.2 (ADR-0005).

- `adda hook install` is installed on ADDA's own `.git/hooks/pre-commit` — this repo now enforces its own doc-gate on every commit. `adda doctor .` proves it on any clone, since the hook is never cloned and fails open (ADR-0015).
- Two adversarial-review passes ran before the v0.1.0 and v0.2.0 tags.
